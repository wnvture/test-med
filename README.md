# Разбор заказов и динамика анализов

Тестовое задание, задачи 1 и 5. Python 3 и MySQL 8. Для первого запуска достаточно Python. Docker не требуется.

| Файл | Назначение |
|---|---|
| `orders.txt` | Исходное сообщение с тремя заказами из условия |
| `orders.py` | Разбор сообщения, расчёт расхода, сохранение в MySQL |
| `analyses.sql` | Таблица с вымышленными анализами и запрос по заданию 5 |
| `README.md` | Запуск, примеры и объяснение решения |

## Первый запуск на Mac

1. Распакуй архив и открой папку `pharmacy-simple` в Finder.
2. Открой Терминал через Spotlight (⌘ + пробел). Набери `python3`, поставь пробел, перетащи **файл `orders.py`** из Finder в окно Терминала и нажми Enter. Терминал сам подставит путь. Скрипт найдёт `orders.txt` рядом с собой.
3. В Finder рядом с `orders.txt` появится `orders.json`. Открой его в редакторе. Внутри три заказа. В терминале появится расход.

Если терминал уже открыт в папке проекта, та же команда короче.

```sh
python3 orders.py
```

Ожидаемый вывод

```text
JSON: orders.json
Прогестерон: 100 мг
Эстриол: 2 мг
N-Ацетилцистеин: 650 мг
```

## Задание 1. От строки из чата до результата

Второй и третий заказы показывают почти всю логику. Во втором заказе написано `Колво: 3` и `NАцетилцистеин  200 мг`. В третьем — `Кол-во: 1` и `N-Ацетилцистеин - 50 мг`. В итоге нужно получить одно название вещества и одну сумму.

**Сначала читаем файл.** Начни читать `orders.py` с функции `main()`. Переменная `text` содержит сообщение целиком. Строка `orders = parse_orders(text)` передаёт его функции разбора. Переменная `orders` получит список заказов.

**Разбираем строки.** В `parse_orders` цикл берёт по одной строке. Шаблон `HEADER` узнаёт заголовок и извлекает номер, форму, срок и количество. `Кол-?во` означает, что дефис может присутствовать или отсутствовать. Если найден заголовок, создаём заказ с пустым списком `components`. Шаблон `COMPONENT` извлекает из следующей строки название и дозировку. `orders[-1]` — последний созданный заказ, а `append` добавляет в него компонент. Если строка непонятна, программа показывает её номер. Дозировка задаётся в мг, допускаются точка и запятая, до трёх знаков после разделителя.

**Приводим название к одному написанию.** После разбора компонента проверяем известные варианты имени N-ацетилцистеина. Оба получают имя `N-Ацетилцистеин`, поэтому в отчёте они складываются. Дефисы в других названиях сохраняются.

**Считаем расход.** Функция `calculate_totals` проходит по каждому компоненту каждого заказа. `used = component['dosage_mg'] * order['quantity']` даёт расход в одном заказе. Затем прибавляем `used` к сумме для этого названия. Для точных вычислений с десятичными дозировками используем `Decimal`.

| Компонент | Расчёт | Итог |
|---|---|---:|
| Прогестерон | 50 × 2 | 100 мг |
| Эстриол | 1 × 2 | 2 мг |
| N-Ацетилцистеин | 200 × 3 + 50 × 1 | 650 мг |

Срок хранится в `duration_days`. По условию он не участвует в формуле расхода.

**Записываем JSON.** `json.dumps` превращает список заказов в текст JSON. `write_text` записывает его в файл. Например, внутри второго заказа поле `quantity` равно `3`, а список `components` содержит `{"name": "N-Ацетилцистеин", "dosage_mg": 200}`. Каждый запуск обновляет JSON рядом с выбранным входным файлом.

## Сохранение заказов в MySQL

Для этой части нужны доступ к работающему серверу MySQL 8, имя пользователя и пароль. Можно использовать уже установленный MySQL или сервер, к которому есть доступ. В примере ниже сервер работает на этом компьютере, пользователь — `root`. Команды выполняются в Терминале из папки проекта. Чтобы в неё перейти, набери `cd`, поставь пробел, перетащи папку из Finder и нажми Enter.

Один раз создай базу в клиенте MySQL. При наличии команды `mysql` это можно сделать так.

```sh
mysql -u root -p -e "CREATE DATABASE IF NOT EXISTS pharmacy_test CHARACTER SET utf8mb4;"
```

Установи в окружение проекта библиотеку, через которую Python подключается к MySQL, и выполни сохранение.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install mysql-connector-python
.venv/bin/python orders.py --save
```

Введи пароль **от MySQL**. Терминал скрывает символы при вводе пароля. Если база на другом компьютере или у тебя другое имя пользователя, передай `--host АДРЕС --user ИМЯ` в последней команде. База должна называться `pharmacy_test`. Для следующих сохранений достаточно последней команды.

**Что делает `save_to_mysql`.** В условии нужно сохранить разобранный JSON, поэтому используем одну таблицу `chat_orders`. В ней одна строка на сообщение. Поле `orders_json` содержит заказы этого сообщения. Поле `message_hash` — отпечаток исходного текста. SQL-команда `INSERT` сохраняет JSON, а `commit()` подтверждает запись. При повторном запуске на том же сообщении обновляется та же строка. Изменённый текст считается отдельным сообщением. Для настоящего чата с уникальными ID сообщений можно было бы использовать сам ID.

Обычный запуск показывает расход для одного файла. Запуск с `--save` читает сообщения из базы и считает общий расход по всем сохранённым заказам той же функцией `calculate_totals`.

Чтобы увидеть запись в базе, выполни SQL в MySQL Workbench или другом клиенте.

```sql
SELECT JSON_PRETTY(orders_json) FROM pharmacy_test.chat_orders;
```

## Задание 5. Что изменилось между двумя анализами

В `analyses.sql` две части. Верхняя создаёт временную таблицу в текущем соединении и добавляет вымышленные измерения. Нижняя, от `WITH comparison` до конца, — ответ на задание. Можно выполнить весь файл в MySQL Workbench, выбрав базу `pharmacy_test`, или запустить из Терминала в папке проекта.

```sh
mysql --default-character-set=utf8mb4 -u root -p pharmacy_test < analyses.sql
```

| Пациент | Показатель | Первое | Последнее | Изменение, % | Статус |
|---:|---|---:|---:|---:|---|
| 1 | А | 8 | 5 | −37,50 | вошёл в норму |
| 1 | Б | 5 | 8 | 60,00 | вышел из нормы |
| 2 | А | 4 | 6 | 50,00 | без изменений |
| 3 | А | 0 | 2 | NULL | вошёл в норму |

**Как читать запрос.** Разберём пациента 1 и показатель А. По датам его значения идут в порядке `8, 9, 5`, а диапазон нормы — от 4 до 6 включительно.

1. `PARTITION BY patient_id, indicator` собирает вместе измерения одного показателя у одного пациента. `ORDER BY analysis_date` ставит их в хронологическом порядке. В демонстрационных данных время измерения внутри этой группы уникально. Если реальная таблица допускает одинаковое время, для однозначного порядка потребуется дополнительный ключ измерения.
2. `FIRST_VALUE(value)` берёт первое значение — 8. `ROW_NUMBER()` нумерует измерения 1, 2, 3. `LEAD(analysis_date)` смотрит дату следующего измерения. У последней строки следующей даты нет (`NULL`). Поэтому условие `next_date IS NULL AND measurement_no >= 2` оставляет последнюю строку только в группах с двумя и более измерениями. У пациента 4 по одному измерению разных показателей, и он в отчёт не попадает.
3. На последней строке доступны оба числа — первое 8 и текущее 5. Процент равен `(5 − 8) × 100 / 8 = −37,5`. Если первое значение ноль, `NULLIF` превращает знаменатель в `NULL`, и процент остаётся неопределённым.
4. `BETWEEN` проверяет значение по границам именно этого измерения. `CASE` выбирает статус. Было 8 (вне диапазона), стало 5 (в диапазоне), значит «вошёл в норму». У пациента 2 было 4 и стало 6, то есть оба результата в диапазоне. Его статус «без изменений», хотя число выросло на 50%.

## Две короткие правки для тренировки

**Поменять данные.** Скопируй `orders.txt` в `practice.txt`. В первой строке копии замени `Кол-во: 2` на `Кол-во: 4`. Выполни `python3 orders.py practice.txt`. Ожидай 200 мг прогестерона и 4 мг эстриола. N-Ацетилцистеин останется 650 мг, потому что он входит в другие заказы.

**Поменять код.** Найди в `main()` строку `orders = parse_orders(text)`. Сразу под ней с тем же отступом добавь `print('Заказов в сообщении:', len(orders))`. При следующем запуске первая строка будет `Заказов в сообщении: 3`. `len()` считает элементы списка, а каждый элемент здесь представляет один заказ.

При подготовке кода, примеров и документации использовался ChatGPT (Codex). Разбор, запись, повторный импорт и запрос по анализам проверены на Python 3.12 и MySQL 8.0.44.
